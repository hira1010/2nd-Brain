# ゲーム制作の極意：モックアップ駆動開発 (MDD)

このドキュメントは、[AI×ゲーム開発入門｜猫宮みいあ](https://note.com/nekomiya_miia/n/nae0af2e207cc) から学んだ、AIと協力して最速でゲームを形にするためのガイドラインです。

## 1. 基本的なマインドセット

- **いきなりコードを書かない**: 最初に「完成予想図（モックアップ）」を作り、視覚的にゴールを定義する。
- **逆算の美学**: 画面から必要な素材（アセット）と機能（TODO）を導き出す。
- **小さく作って、速く回す**: 「一度で完成」は目指さない。表示 → 操作 → 攻撃 → 勝敗 の順に少しずつ足していく。

## 2. 実装のステップ

1.  **モックアップ作成**: ChatGPT/AIに「対戦画面のイメージ」を作らせ、納得いくまで調整する。
2.  **TODO.mdへの分解**: モックアップを基に、作業を「素材作成」と「実装」に細かく分ける。
3.  **アセット用意**: 画像生成AIなどを使い、まずは「仮素材」を揃える。
4.  **Canvas表示**: まずは「画面に出る」ことを確認する。
5.  **ロジック追加**: 移動、攻撃、吹っ飛び、K.O.判定を段階的に実装する。
6.  **ブラウザで確認**: 常に動かしながら、違和感をその場でAIに修正させる。

## 3. AI（Antigravity）への頼み方

- **画面単位で依頼する**: 「タイトル画面担当」「リザルト画面担当」のように、役割を限定して指示する。
- **触ってよい範囲を指定する**: 修正してほしいファイルと、壊してほしくないファイルを明確に伝える。
- **TODOを渡す**: 「TODO.mdの上から順番に実装して」と頼むことで、AIの迷いをなくす。

## 4. AIへ「使えるコード」を出力させるためのコツ

このセクションは、[生成AIに本当に使えるコードを出力してもらいたい｜AI×Unityゲーム開発スターターキット](https://zenn.dev/ohbashunsuke/books/unity-ai-starter-kit/viewer/unity-ai-starter-kit-01) から学んだ重要なエッセンスです。

- **「ルールブック」を必ず用意する**:
  AIに大雑把に頼むと、「画面の仕組み」と「ルールの仕組み」がごちゃ混ぜになり、あとで修正できなくなります。これを防ぐため、事前にプロジェクト内に `CLAUDE.md` や `AGENTS.md` のようなAI専用のルールブック（指示書）ファイルを作成して置いておくことが、成功への一番の近道です。
- **ルールブックに書くべき内容**:
  - 表示（View）とルール（Logic）を分けて作ること
  - プログラムの名前の付け方のルール
  - 絶対にやってはいけない書き方（禁止事項）
- **丸投げせずコントロールする**:
  AIが書いてきたコードがルールを守っているか常にチェックし、一気に作らず小さなパーツごとに少しずつ進めることが大切です。

## 5. AIへの具体的な指示の出し方（プロンプトのコツ）

このセクションは、[Step 1 プロジェクトの土台の開発](https://zenn.dev/ohbashunsuke/books/unity-ai-starter-kit/viewer/unity-ai-starter-kit-03) から学んだ、AIの暴走を防ぐテクニックです。

- **最初は「動かない土台」だけを作らせる**:
  いきなりゲームの機能（スコアや操作など）を作らせてはいけません。最初は「ファイルだけ」「空っぽの設計図だけ」を作らせるよう、極限まで小さなステップで指示を出します。
- **AIの「おしゃべり」を制限する**:
  「設計メモは3〜5行で」「不要なプログラム一覧は書かないで」とプロンプトで文字数制限をかけることで、AIが脱線して不要なコードを書くのを防ぎます。
- **「自分で確認して直して」と指示に混ぜる**:
  指示の最後に「完成したら自分でエラーチェックして、間違っていたら直してね」と一言添えることで、人間がエラーを直す手間を減らします。
- **フォルダ分けで「物理的な壁」を作る**:
  AIが勝手に別のプログラムを壊さないように、フォルダで役割（画面用、ルール用など）をハッキリ分けます。
- **AIが勝手にやりすぎたら「差し戻す」**:
  頼んでいない機能までAIが作ってしまった場合は、「今は土台作りなので、前の段階に戻して」とハッキリ指示して引き戻すことが大切です。

## 6. 他のゲームでも使える！AI開発の応用テクニック

このセクションは、[AI×Unityゲーム開発スターターキット](https://zenn.dev/ohbashunsuke/books/unity-ai-starter-kit) の各章（無料公開部分）から抽出した、どんなゲームにも応用できる汎用的なノウハウです。

- **「1個だけ」で動く最小パーツから作る**:
  例えば、たくさんの敵が出るゲームを作る場合でも、まずは「敵が1体だけ出て、正しく動くか」を確認します。最初から大量のものを制御させようとすると、AIは高確率で混乱します。
- **派手な演出（見た目）は一番最後に回す**:
  「ヒットした時のエフェクト」や「かっこいいアニメーション」などは、ゲームの基本ルール（攻撃が当たったらライフが減るなど）が完璧に動くようになってから追加します。見た目とルールを同時に作らせると、プログラムが複雑になりすぎてAIがバグを生みやすくなります。
- **「仮の数字（ダミーデータ）」でテストする**:
  スコア機能やタイマー機能などを作る際は、まずは「10秒経ったら終わり」「1点入ったら勝ち」のような、確認しやすい簡単な数字でAIにプログラムを作らせます。本番用の細かい調整（例：制限時間90秒、コンボでボーナス点など）は、仕組みが完成した後に少しずつ変更します。
- **エラーが出たら「コード全体」を渡す**:
  AIが作ったプログラムでエラーが出た場合、エラー文だけを渡すのではなく、関係するプログラムのコード全体をセットで渡すと、AIはどこが間違っているのかを正確に判断しやすくなります。
